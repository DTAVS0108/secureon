# Hosting platforms (one click)

Ready-made templates start SecureOne with its PostgreSQL database and Redis on a hosting platform, with every
setting already filled in: the image, the port, the health check, the database and Redis addresses and a generated
encryption key. You enter only the address people will use. When it is running, open that address followed by
**/admin/setup** to finish the setup in the browser.

| Platform | How you start it | You enter |
|---|---|---|
| Render | The **Deploy to Render** button | `SECUREONE_PUBLIC_BASE_URL` |
| Portainer | App Templates, or a stack from the Compose file | Public address and a database password |
| Unraid | Community Apps (with PostgreSQL and Redis from Community Apps) | Public address, database and Redis URLs, an encryption key |
| DigitalOcean App Platform | `doctl apps create --spec app.yaml` | An encryption key (in the file) |

Every template runs the published image `dmtavs0108/secureone:0.1.0`. On a platform without a template (Railway,
Fly.io, a cloud container service), set the same few variables by hand: see [Installation](installation.md#the-variables)
and the Deploy page of the website.

## Render

[Deploy to Render](https://render.com/deploy?repo=https://github.com/DTAVS0108/secureone-deploy) creates three
things in one region: the SecureOne web service, a Render Postgres database and a Render Key Value (Redis). Render
asks for `SECUREONE_PUBLIC_BASE_URL`: enter `https://<service name>.onrender.com`, or your own domain (then add it to
the service under **Settings → Custom Domains**).

- The database address is Render's own `postgresql://` connection URL; SecureOne takes the user and password from it.
- The encryption key is generated by Render as `SECUREONE_ENCRYPTION_KEY`. Copy it from the service's **Environment**
  page and keep it with your backups, apart from the database backups: without it, a database backup cannot be used.
- The plans are paid on purpose: Render's free web plan sleeps (sign-in would stall) and free databases expire.

## Portainer

In Portainer, open **Settings → App Templates** and set the URL to

```
https://raw.githubusercontent.com/DTAVS0108/secureone-deploy/main/portainer/templates.json
```

Then choose **SecureOne** under **App Templates** and fill in the public address and a database password. Or create a
stack (**Stacks → Add stack**) from
`https://github.com/DTAVS0108/secureone-deploy/blob/main/portainer/docker-compose.yml` and set `PUBLIC_URL` and
`DB_PASSWORD`. The encryption key is created in the stack's `secureone-data` volume: back it up.

## Unraid

Install **PostgreSQL 16** and **Redis** from Community Apps first, then SecureOne with the template
`https://raw.githubusercontent.com/DTAVS0108/secureone-deploy/main/unraid/secureone.xml`. Fill in the database URL
(`postgres://user:password@SERVER-IP:5432/secureone`), the Redis URL and an encryption key from
`openssl rand -base64 32` in the Unraid terminal. Keep a copy of the key.

## DigitalOcean App Platform

Download
`https://raw.githubusercontent.com/DTAVS0108/secureone-deploy/main/digitalocean/app.yaml`. The steps are at the top of
the file: create the PostgreSQL and Valkey databases with `doctl`, put an encryption key in the file, then
`doctl apps create --spec app.yaml`.
<!-- /not on website -->

## Before going live

- SecureOne needs an **https** address. Render and DigitalOcean provide one; on Portainer and Unraid, put a reverse
  proxy with a certificate in front of the port.
- Back up the database regularly, and keep the encryption key separately.

## The templates repository

The templates live in a small public repository, [DTAVS0108/secureone-deploy](https://github.com/DTAVS0108/secureone-deploy),
because these platforms read their templates from a public Git repository. It holds only the templates and their
README: no source code, no secrets. Each template names the image version, so a new SecureOne release also updates
the templates there.
